# Field watch — 2026-11-21

Window: 2026-11-13 to 2026-11-21

**TL;DR**

- TypeSafe's side did not change: OpenAPI 0.2.0 as vendored, SDKs at Python 0.7.5 and JS 0.7.0, aliases on `jev-1.14.0`.
- Liquid deprecated `d1`, `d1.1` and `d1-ultra` on 2026-11-16 for `d1.2`/`d1.2-ultra` on the same endpoint; judgment's docs and `live:liquid` still name `d1` (P1).
- ZML llmd now serves the wire; llama.cpp aborts under concurrent requests and vLLM silently remaps letter and digit labels, which `Response::verify` cannot see (two P2 tasks, and one for five papers).

## Impact on judgment

**Breaking risks.** None on TypeSafe's wire. Liquid's `d1` still answers but is deprecated, and the guide still says to name it; `d1:latest` follows the newest model, so a user on that alias may have moved silently. Liquid refuses zstd bodies, so judgment's `zstd` feature fails every request there, unstated in the docs. vLLM's label remapping is worse for judgment than a refusal: an answer naming an offered but wrong option passes `Response::verify`. A live check with letter-like options would catch it. With llama.cpp, keep the `Pacer` to one call in flight until #32713 lands.

**Opportunities.** Liquid, Perplexity and Open System One now put extraction types on the same path; TypeSafe has not (ASK-1).
